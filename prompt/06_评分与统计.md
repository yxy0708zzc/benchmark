# 06_评分与统计.md（给 Trae 的完整提示词）

本文件是 Trae 生成代码时的完整约束文档，涵盖评分指标的汇总计算、多维度对比分析和结论生成的全部内容。

**Trae 使用说明**：本模块读取 `logs/result/` 目录下的所有测评结果 JSON 文件，按不同维度汇总计算各项指标，生成对比报告。本模块为只读分析模块，不修改任何数据。


## 第一部分：输入数据源

### 1.1 数据来源

| 数据源 | 路径 | 内容 |
|--------|------|------|
| 测评结果 | `logs/result/*.json` | 每条测试记录的完整测评数据（含需求列表、逐条得分、归百分、造假标记） |
| 测试记录 | `logs/test/*.json` | 测试时的原始记录（含 token 用量、工具调用次数、对话轮次） |

**关联方式**：测评结果 JSON 中的 `test_file` 字段指向对应的测试记录文件路径。

### 1.2 测评结果 JSON 的关键字段（用于统计）

```json
{
  "question_id": "q003",
  "model_name": "deepseek-v3",
  "requirements": [
    {"text": "出发地是北京南", "achieved": 2},
    {"text": "需要2张票", "achieved": 0}
  ],
  "score_summary": {
    "total_requirements": 5,
    "sum_scores": 7,
    "average": 1.4,
    "normalized": 70
  },
  "verification": {
    "is_fraud": false
  },
  "status": "success"  // 或 "no_solution"
}
```


## 第二部分：统计指标定义与计算公式

### 2.1 指标总览

| 指标名称 | 类型 | 数据来源 | 说明 |
|----------|------|----------|------|
| 完成率 | 核心指标 | `status` | 成功完成任务的比例 |
| 幻觉率 | 核心指标 | `verification.is_fraud` | 声称有票但实际无票的比例 |
| 限制实现率 | 核心指标 | `requirements[].achieved` | 每条需求的平均实现程度 |
| 可行率 | 辅助指标 | 方案时间衔接 | 方案在时间上是否可执行 |
| Token 消耗 | 效率指标 | `logs/test/` 中的 `token_usage` | 平均每次测试消耗的 token 数 |
| 加载时间 | 效率指标 | `logs/test/` 中的 `duration` | 平均每次测试耗时（秒） |
| 工具调用次数 | 行为指标 | `logs/test/` 中的 `tool_calls` | 平均每次测试调用工具次数 |

### 2.2 各指标计算公式

#### 完成率（Completion Rate）

```
完成率 = (成功完成数 / 总测试数) × 100%
```

- **成功完成**：`status = "success"`（模型给出了可执行的购票方案）
- **失败**：`status = "no_solution"`（模型表示无法买到票）

#### 幻觉率（Hallucination Rate）

```
幻觉率 = (造假数 / 成功完成数) × 100%
```

- **造假**：`verification.is_fraud = true`（声称有票但数据库核实无票）
- 分母为成功完成数（只有声称有票的才可能造假）

#### 限制实现率（Constraint Achievement Rate）

```
限制实现率 = (所有需求得分的总和 / (需求总数 × 2)) × 100%
```

- 每条需求最高 2 分
- 等价于所有测评结果中 `score_summary.normalized` 的平均值
- 也可分项统计：分别计算出发地、目的地、时间、座位、票数等不同类型需求的平均得分

#### 可行率（Feasibility Rate）

```
可行率 = (方案中时间衔接合理的数量 / 成功完成数) × 100%
```

- **时间衔接合理**：换乘方案中，前一趟到达时间 < 后一趟出发时间，且间隔 ≥ 15 分钟
- 从模型输出的方案中提取时间信息进行判断
- 直达方案默认可行（只要票真实存在）

#### Token 消耗（Token Usage）

```
平均 Token 消耗 = 总 token 数 / 测试总数
```

- 从 `logs/test/` 的 `token_usage.total_tokens` 字段汇总
- 可分别统计 `prompt_tokens` 和 `completion_tokens`

#### 加载时间（Response Time）

```
平均加载时间 = 总耗时 / 测试总数
```

- 从 `logs/test/` 的 `duration` 字段（单位：秒）
- 指从发送请求到收到完整响应的时间

#### 工具调用次数（Tool Call Count）

```
平均工具调用次数 = 总调用次数 / 测试总数
```

- 从 `logs/test/` 的 `tool_calls` 数组长度汇总


## 第三部分：对比维度

### 3.1 按模型横向对比

**场景**：同一组题目，测试多个不同模型（如 deepseek-v3、gpt-4、claude-3.5）

**对比表格**：

| 指标 | deepseek-v3 | gpt-4 | claude-3.5 |
|------|-------------|-------|------------|
| 完成率 | 85% | 90% | 80% |
| 幻觉率 | 5% | 2% | 8% |
| 限制实现率 | 78分 | 85分 | 72分 |
| 可行率 | 90% | 95% | 85% |
| 平均 Token | 2300 | 1800 | 2500 |
| 平均耗时 | 3.2s | 2.1s | 4.5s |
| 平均工具调用 | 4.2次 | 3.5次 | 5.1次 |

### 3.2 按题目类型纵向对比

**场景**：同一模型，在不同题型（直达/换乘/买短补长/同车换乘/混合）上的表现

**对比表格**：

| 指标 | 直达题 | 换乘题 | 买短补长题 | 同车换乘题 | 混合题 |
|------|--------|--------|------------|------------|--------|
| 完成率 | 95% | 85% | 80% | 75% | 60% |
| 幻觉率 | 2% | 4% | 6% | 8% | 10% |
| 限制实现率 | 92分 | 78分 | 72分 | 68分 | 55分 |

### 3.3 按难度/干扰密度对比

**场景**：同一模型，在不同干扰密度（0.05、0.15、0.25）的题目上的表现

### 3.4 按座位类型对比

**场景**：用户需求为不同座位类型（class0/class1/class2）时，模型的成功率和实现率差异


## 第四部分：结论生成

### 4.1 自动生成的结论内容

统计模块应自动生成以下结论：

**1. 模型排名**（按归一化得分降序）

```
模型综合排名：
1. gpt-4（平均分 85）
2. deepseek-v3（平均分 78）
3. claude-3.5（平均分 72）
```

**2. 各模型优缺点总结**

从分项指标中自动提取：
- **优势项**：该模型得分最高的 2 个指标
- **劣势项**：该模型得分最低的 2 个指标

**3. 题型难度排序**

```
题型难度排序（从易到难）：
1. 直达题（平均分 92）
2. 换乘题（平均分 78）
3. 买短补长题（平均分 72）
4. 同车换乘题（平均分 68）
5. 混合题（平均分 55）
```

**4. 幻觉率警告**

如果某模型幻觉率 > 10%，输出警告信息。
