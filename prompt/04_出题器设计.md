# 04_出题器设计.md（给 Trae 的完整提示词）

本文件是 Trae 生成代码时的完整约束文档，涵盖出题器全部内容：手动出题器、auto出题器、改题器三个独立组件的功能设计、交互流程、数据操作逻辑和前端界面要求。

**Trae 使用说明**：按以下顺序实现三个组件。手动出题器和改题器共用一套前端组件（矩阵渲染、实时写入），auto出题器有独立前端。所有出题器只能修改余票数据，不能修改基础数据。


## 第一部分：全局概念与数据模型

### 1.1 题目文件结构

```
question/
├── metadata.json          # 题目元数据
├── q001.db                # 题目数据库
├── q002.db
├── q_auto_001.db
└── ...
```

### 1.2 题目数据库结构（qXXX.db）

每个题目数据库包含三张表，结构完全相同：

**class2**（二等座）：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PRIMARY KEY | 自增主键 |
| train_num | TEXT | 车次号 |
| from_station_id | TEXT | 出发站电报码 |
| to_station_id | TEXT | 到达站电报码 |
| tickets | INTEGER | 余票数量，0~30 |

**class1**（一等座）：结构同上

**class0**（特等座）：结构同上

**约束**：
- `(train_num, from_station_id, to_station_id)` 组合唯一
- 所有 `train_num` 必须存在于 `data/railway.db` 的 `trains` 表中
- 所有 `from_station_id` 和 `to_station_id` 必须存在于 `data/railway.db` 的 `stations` 表中
- `tickets` 值域 0~30
- 只存储 `from_station_id` 的站序 < `to_station_id` 的站序 的记录（半矩阵）
- 每个有效站对都必须有一条记录，无票时 `tickets = 0`

### 1.4 全局规则（所有“器”通用）

| 规则 | 说明 |
|------|------|
| 基础数据只读 | 所有“器”只能修改余票矩阵，不能修改车次号、经停站、车站名等基础数据 |
| 车站校验 | 所有 `from_station_id` 和 `to_station_id` 必须存在于 `stations` 表中，否则拒绝操作 |
| 值域限制 | 余票数量 0~30 的整数 |
| 保存前确认 | 任何保存操作之前，必须弹窗让用户确认 |
| 半矩阵约束 | 只显示和存储 `stop_no` 小的站 → `stop_no` 大的站，反向不存储 |


## 第二部分：手动出题器

### 2.1 功能概述

用户通过输入车次号，逐车次填写余票数据，所有车次填完后保存为一道完整的题目。

### 2.2 核心特性

| 特性 | 说明 |
|------|------|
| 默认值 | 进入时所有格子默认显示 `0` |
| 实时写入 | 修改格子后立即写入数据库，不是内存暂存 |
| 多车次支持 | 同一 `qXXX.db` 可填多个车次，逐个输入车次号切换 |
| 随机填充 | 点击随机按钮，当前车次所有站对随机生成 0~30 |
| 保存 | 标记该题目 `status = "completed"`，供测试器识别 |
| 放弃 | 关闭页面或取消，不改变状态（数据仍保留为草稿） |

### 2.3 前端界面要求

**布局**：

```
┌─────────────────────────────────────────────────┐
│  出题器                                        │
│  当前题目：q003   状态：草稿                    │
│  车次号：[G1] [加载]                           │
│  已填车次：G1, G3, G5, G7                     │
│                                                 │
│  半矩阵表格：                                   │
│  ┌──────────────────────────────────┐          │
│  │ 出发\到达 │ 济南西 │ 南京南 │ 上海虹桥 │ │
│  │ 北京南   │  5    │  0    │  12    │ │
│  │ 济南西   │  -    │  3    │  8     │ │
│  │ 南京南   │  -    │  -    │  0     │ │
│  └──────────────────────────────────┘          │
│                                                 │
│  [随机填充当前车次]  [保存]  [放弃]             │
└─────────────────────────────────────────────────┘
```

**交互流程**：

1. 用户打开出题器页面
2. 选择题目编号（已有草稿继续编辑，或新建 `qXXX`）
3. 输入车次号（如 `G1`），点击加载
4. 前端从 `question/{当前题目}.db` 读取该车次所有站对数据
5. 如果该车次尚无数据，所有格子显示 `0`（此时数据库中该车次所有站对记录已存在，`tickets=0`）
6. 用户修改任意格子（输入 0~30 的整数），**修改后立即写入数据库**
7. 可切换其他车次继续填写
8. 点击“保存” → 弹窗确认 → 更新 `metadata.json` 中该题目的 `status = "completed"`
9. 点击“放弃” → 关闭页面，不改变状态

### 2.4 新建题目逻辑

**新建时**：
1. 生成新的编号（如 `q003`）
2. 在 `question/` 下创建 `q003.db` 文件
3. 创建 `class0`、`class1`、`class2` 三张空表
4. 但此时表中没有任何数据记录

**首次加载车次时**：
1. 从 `data/railway.db` 读取该车次的经停站列表
2. 计算所有有效站对（`N*(N-1)/2` 个）
3. 在 `class0`、`class1`、`class2` 三张表中插入所有站对记录，`tickets=0`
4. 然后前端显示矩阵，所有格子为 `0`

**已加载过的车次**：
1. 直接读取该车次现有数据
2. 前端显示矩阵，格子值为数据库中的 `tickets` 值

### 2.5 实时写入的代码实现

```python
# 用户修改一个格子时调用
def update_ticket(question_id, train_num, from_station_id, to_station_id, seat_type, tickets):
    db_path = f"question/{question_id}.db"
    conn = sqlite3.connect(db_path)
    cursor = conn.cursor()
    # 校验车站是否存在（代码层）
    if not station_exists(from_station_id) or not station_exists(to_station_id):
        raise ValueError("车站不存在")
    # 更新或插入
    cursor.execute("""
        INSERT OR REPLACE INTO {seat_type}
        (train_num, from_station_id, to_station_id, tickets)
        VALUES (?, ?, ?, ?)
    """, (train_num, from_station_id, to_station_id, tickets))
    conn.commit()
    conn.close()
    # 更新元数据中的修改时间
    update_metadata(question_id, modified_at=datetime.now())
```

### 2.6 随机填充逻辑

- 点击“随机填充当前车次”按钮
- 仅对当前显示的车次生效
- 遍历该车次所有有效站对，`tickets = random.randint(0, 30)`
- 实时写入数据库
- 前端矩阵同步刷新

**重要**：随机填充只影响当前车次，不影响 `qXXX.db` 中其他车次的数据。


## 第三部分：auto出题器

### 3.1 功能概述

用户输入目标区间和题型参数，系统自动生成一道完整的题目（含全国所有车次的余票数据，其中目标车次按题型构造，其余车次随机生成干扰项）。

### 3.2 核心特性

| 特性 | 说明 |
|------|------|
| 一次性生成 | 每次生成一道完整题目 |
| 五种题型 | 直达、换乘、买短补长、同车换乘、混合 |
| 自动匹配车次 | 用户只指定区间，系统随机选一个经过该区间的车次作为目标车次 |
| 其他车次 | 按干扰密度随机生成余票（让数据真实） |
| 预览确认 | 生成后预览矩阵和合法路径，用户确认后才写入文件 |
| 放弃 | 预览阶段可放弃，不保存任何文件 |

### 3.3 参数配置

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `question_type` | string | 是 | - | `direct` / `transfer` / `short_buy` / `same_train` / `mixed` |
| `from_station_id` | string | 是 | - | 目标出发站电报码 |
| `to_station_id` | string | 是 | - | 目标到达站电报码 |
| `interference_density` | float | 否 | 0.15 | 干扰项密度，0.05~0.30 |
| `solution_ticket_min` | int | 否 | 1 | 合法解最小票数 |
| `solution_ticket_max` | int | 否 | 5 | 合法解最大票数 |
| `mixed_strategies` | array | 否 | [] | 混合策略列表，如 `["transfer", "short_buy"]`（仅当 `question_type=mixed` 时生效） |
| `output_prefix` | string | 否 | `q_auto_` | 输出文件名前缀 |
| `seed` | int | 否 | 随机 | 随机种子（可选，用于复现） |

### 3.4 题型逻辑

**所有题型的共同前置步骤**：
1. 根据 `from_station_id` 和 `to_station_id`，从 `train_stops` 表查询经过这两个站的所有车次
2. 随机选择其中一个车次作为目标车次（记为 `target_train_num`）
3. 获取该车次的经停站列表，按 `stop_no` 排序
4. 确认 `from_station_id` 和 `to_station_id` 在该车次上的站序：`from_no < to_no`（若 `from_no > to_no`，交换二者，因为半矩阵只存前向站→后向站）
5. 将该车次所有站对的 `tickets` 初始化为 0（清空该车次全部余票）
6. 然后按题型执行特定逻辑

#### 题型1：直达（direct）

**考点**：模型识别直达是最优解

**挖空**：将该区间所有中转路径的票清为 0（换乘题中才用，直达题不需要额外挖空，因为初始已清空所有票）

**合法解构造**：
- 目标区间 `from_station_id → to_station_id` 设置 `tickets = random.randint(solution_ticket_min, solution_ticket_max)`
- 其他站对保持 0（无中转路径有票，直达是唯一可行方案）

#### 题型2：换乘（transfer）

**考点**：模型发现换乘路径

**合法解构造**：
- 从该车次的经停站中，随机选一个中间站 C（满足 `from_no < C_no < to_no`）
- `from_station_id → C` 设置 `tickets = random.randint(solution_ticket_min, solution_ticket_max)`
- `C → to_station_id` 设置 `tickets = random.randint(solution_ticket_min, solution_ticket_max)`
- 目标区间 `from_station_id → to_station_id` 保持 0（无直达票）

**重要**：系统只保证**同一车次**的换乘路径（A→C 和 C→B 在同一车次上）。如果该车次没有合适的中间站，则重新选择车次。

#### 题型3：买短补长（short_buy）

**考点**：模型使用买短补长策略（买到中途站，车上补票）

**合法解构造**：
- 从该车次的经停站中，随机选一个站 C（满足 `from_no < C_no < to_no`），即 C 在到达站之前
- `from_station_id → C` 设置 `tickets = random.randint(solution_ticket_min, solution_ticket_max)`
- 补票段 `C → to_station_id` 在矩阵中保持 0（不填票，因为补票不通过余票系统）
- 目标区间 `from_station_id → to_station_id` 保持 0（无直达票）
- 其他站对保持 0

#### 题型4：同车换乘（same_train）

**考点**：模型识别同一车次分段购票

**合法解构造**：
- 从该车次的经停站中，随机选一个中间站 C（满足 `from_no < C_no < to_no`）
- `from_station_id → C` 设置 `tickets = random.randint(solution_ticket_min, solution_ticket_max)`
- `C → to_station_id` 设置 `tickets = random.randint(solution_ticket_min, solution_ticket_max)`
- 目标区间 `from_station_id → to_station_id` 保持 0（无直达票）

**与换乘题的区别**：换乘题只告诉大模型有 A→C 和 C→B 的票，但可能是同一车次也可能是不同车次。大模型需要调用 `query_train_detail` 确认是否为同一车次。

#### 题型5：混合（mixed）

**考点**：模型同时使用多种策略

**合法解构造**：
- 用户通过 `mixed_strategies` 参数指定需要同时存在的策略组合（如 `["transfer", "short_buy"]`）
- 系统同时构造多条合法路径：
  - 换乘路径：A→C 和 C→B 有票
  - 买短补长路径：A→D 有票（D 在 B 之前）
- 所有路径的票均设置 `tickets = random.randint(solution_ticket_min, solution_ticket_max)`
- 目标区间直达票保持 0

**约束**：至少选择 2 个策略，且策略之间不矛盾（如同车换乘 + 换乘可以并存，直达 + 换乘不能并存）

### 3.5 干扰项生成

**步骤**：合法解构造完成后，遍历全国所有 G 车次的所有站对，以 `interference_density` 的概率设置随机票数。

**伪代码**：

```python
def generate_interference(db, density, max_tickets):
    # 获取所有 G 车次
    trains = get_all_train_nums()
    for train_num in trains:
        stops = get_train_stops(train_num)
        for i in range(len(stops)):
            for j in range(i + 1, len(stops)):
                from_id = stops[i].station_id
                to_id = stops[j].station_id
                # 跳过目标车次的目标区间（不破坏合法解）
                if train_num == target_train_num and from_id == target_from and to_id == target_to:
                    continue
                # 跳过合法解的站对（不破坏合法路径）
                if is_part_of_solution(train_num, from_id, to_id):
                    continue
                # 以 density 概率生成干扰票
                if random.random() < density:
                    tickets = random.randint(1, max_tickets)
                    update_tickets(db, train_num, from_id, to_id, tickets)
```

**三张座位表都要生成干扰项**，但每个座位的干扰项独立生成（密度相同，随机值独立）。

**修改**：这确保了三张座位表的干扰分布各不相同，符合真实场景中不同座位类型余票情况独立的特点。

## 第五部分：前端通用组件

### 5.1 半矩阵渲染组件

手动出题器和改题器共用同一套矩阵渲染组件：

**输入**：
- `train_num`：车次号
- `stops`：经停站列表（按 `stop_no` 排序）
- `data`：该车次所有站对的余票数据（三张表合并）

**输出**：
- HTML 表格，行和列均为 `stops` 列表
- 只显示右上三角（行索引 < 列索引）
- 对角线显示 `-`（不可编辑）
- 左下三角显示 `-`（不可编辑，灰色）
