## 第一部分：项目概述

### 1.1 项目名称

**高铁购票大模型能力测试平台（Benchmark）**

### 1.2 项目目标

构建一个用于测试和评估大模型（如 DeepSeek、GPT-4、Claude 等）在**复杂规划、组合推理和工具调用**方面能力的 Benchmark 平台。

**核心场景**：用户提出高铁购票需求（如“从北京南到上海虹桥，今天下午出发，二等座，2张票”），大模型需要理解意图、调用工具查询数据、组合多种购票策略（直达、换乘、买短补长等），最终给出可执行的购票方案。

### 1.3 核心价值

| 维度 | 说明 |
|------|------|
| 真实数据 | 基于 12306 真实车次和经停站数据 |
| 可控评测 | 通过自定义余票数据，精确控制题目难度和考点 |
| 自动化流程 | 出题 → 测试 → 测评 → 统计，全流程闭环 |
| 多模型对比 | 同一题目集横向对比不同模型表现 |
| 量化指标 | 完成率、幻觉率、限制实现率、Token 效率等 7 项核心指标 |

## 第四部分：实现顺序建议

Trae 应按以下顺序生成代码，确保每步都有前置依赖：

### 阶段一：数据层（基础）

**顺序**：`01_数据爬取与数据库设计.md`

**产出**：
- 爬虫脚本（`collector.py`）
- 数据库初始化脚本（`database.py`）
- 车站列表采集（`stations.py`）
- 运行后生成 `data/railway.db`

**验证标准**：`data/railway.db` 中四张表均有数据，`stations` 表至少有 1000 条记录，`trains` 表至少有 500 条 G 车次记录。

### 阶段二：服务层（API + Tools）

**顺序**：`02_API与工具定义.md`

**产出**：
- FastAPI 服务（`server.py`）
- 6 个端点实现
- 6 个 Tools 定义（OpenAI 格式）
- 工具注册和状态管理

**验证标准**：`curl http://127.0.0.1:8000/api/train` 返回车次列表 JSON，格式正确。

### 阶段三：出题器（数据生成）

**顺序**：`04_出题器设计.md`

**产出**：
- 手动出题器前端 + 后端
- auto出题器前端 + 后端
- 改题器前端 + 后端（复用）
- 元数据管理（`metadata.json` 读写）

**验证标准**：通过手动出题器生成 `q001.db`，`metadata.json` 中 `q001.status = "completed"`。

### 阶段四：测试器与测评器（核心功能）

**顺序**：`03_提示词设计.md` + `05_测试器与测评器设计.md`

**产出**：
- 提示词常量（`SYSTEM_PROMPT`、`EVAL_PROMPT`）
- 测试器前端 + 后端
- 测评器前端 + 后端
- 日志管理（`logs/test/`、`logs/result/`）

**验证标准**：选择 `q001` 题目，输入一条购票需求，模型返回方案，`logs/test/` 下生成 JSON 文件。

### 阶段五：统计面板（分析）

**顺序**：`06_评分与统计.md`

**产出**：
- 数据聚合器（`aggregator.py`）
- 对比分析器（`comparer.py`）
- 报告生成器（`reporter.py`）
- 统计面板前端

**验证标准**：`logs/result/` 下有至少 3 条测评记录，统计面板显示模型排名和题型难度排序。

### 阶段六：前端美化（全站）

**顺序**：`08_前端设计规范与交互要求.md`

**产出**：
- 全局 CSS（`styles.css`）
- 主应用逻辑（`app.js`）
- 可复用组件（`components.js`）
- 所有页面 HTML

**验证标准**：所有页面配色统一、矩阵表格可编辑、响应式适配 1440px 和 1024px 断点。

### 阶段七：集成测试与联调

**验证标准**：
1. 完整跑通一条测试链路：出题 → 测试 → 测评 → 统计
2. 所有路径使用 `07_全局命名规范.md` 中定义的字段名

## 第六部分：代码规范要求

### 6.1 Python 代码

- Python 3.10+
- 使用类型注解（Type Hints）
- 函数和类包含 docstring
- 关键逻辑包含中文注释
- 使用 `sqlite3`（标准库，无需额外依赖）
- FastAPI + Uvicorn

### 6.2 前端代码

- 原生 HTML + CSS + JavaScript（无框架依赖）
- CSS 变量统一管理配色
- 使用 Lucide Icons
- 图表使用 Chart.js 或 ECharts（CDN 加载）

### 6.3 依赖管理

```txt
fastapi==0.104.1
uvicorn==0.24.0
requests==2.31.0
python-multipart==0.0.6
```

所有依赖写入 `requirements.txt`。

### 6.4 项目启动方式

```bash
# 1. 安装依赖
pip install -r requirements.txt

# 2. 初始化数据库（爬虫）
python collector.py

# 3. 启动 API 服务
python server.py

# 4. 访问前端
# 打开浏览器访问 http://127.0.0.1:8000
```
